# Development Activity Report: universal corrections (national-7), 2026-11-02

Founder brief: "JODY — Universal Development Activity Report corrections". The rules are shared and keyed on what each record's
own words say, never on a place or a source. The Seattle sample (3101 Western Ave, 98121, 0.5 mi) is the regression fixture:
`test/fixtures/report-quality/seattle-3101-western-2026-11-02.json`, a read-only production capture (55 development records).

## What changed

| Area | Before (national-5) | After (national-7) |
|---|---|---|
| Relevance | Interior/unit/repair permits listed in a "Minor Building Work" section | `relevance()` in the engine judges every record before any section, count, map, history, Watch alert or export. Routine work and records whose words establish nothing are left out of the customer report and kept in `relevance_review` (identity, reason, deciding words) for internal review |
| Residential records | Not judged | The canonical residential rule (`lib/residential-qualify.js`, Map 1's gate and the 2026-09-06 provenance ruling) is loaded through a generated byte-for-byte copy and consumed, not restated |
| Stages | "Permitted / Under Construction", "Approved / Coming", "Operating / Built" | "Permit issued" or "Under construction" (from the agency's own word), "Approved" (with "approval is not a construction permit"), "Completed (agency record)" (does not mean occupied or open) |
| Unpublished stage | A connector constant could put a record in Proposed | No stage, unless the agency published an issue date |
| Temporary events | Shown as Proposed while the record stayed open | No stage. The documented window (earliest to latest date in the record's fields or text, set-up and removal included) decides: upcoming and under way are listed with their dates; ended is left out unless a separate continuing scope qualifies; no dates in the full record is left out (`temporary_timing_not_stated`); text cut by ingestion with no full description is left out as `temporary_timing_not_captured`, never as "no dates" |
| Occupancy (#2526, national-6) | Approved / Coming | "Approved for occupancy — business opening not verified", or "Temporary occupancy approved — business opening not verified" for TCO / Temporary C of O, with the agency's exact status beside it. Relevance runs first, so an occupancy approval for routine work is not listed. Presentation only: the change ledger's facts carry no stage label, so no agency-status-change event is created |
| Quality-of-life | Generic warnings by Type on every record | One line per record from what it documents (demolition, change of use to X, building-wide exterior work, land-use application, ...), then the Type's own sentence unchanged, so no note names fewer impacts than before (founder, 2026-11-02). A report saved before national-7 reads the scope-only sentence (founder: "this is fine") |
| Titles | Raw 120-character feed text, cut mid-word | Concise title (agency class word dropped, first sentence, no "per plan"), cut at a word; the full text as "Documented scope" |
| Categories | Jody type only | "Jody type" and "Agency category" side by side |
| Records vs projects | Counts unlabelled | Counts are called record counts; records at one address cross-reference each other and are never called one development |
| Overview | Briefing only | "Most significant nearby changes" first, ranked by what the record documents |
| Map | Legend listed every stage; unmapped records unexplained | Legend lists drawn stages only; numbers run 1..N after filtering; each unmapped row says why |
| Freshness | Generation day only | Generation day and, separately, when Jody last read the records |
| Coverage note | none | The founder's sentence, word for word, plus a note that some nearby records did not describe their work |
| Branding / PDF | "HomeSignal" in disclosure, outcomes, print footer; filter chips printed | Jody throughout, `https://jodytracks.com` on screen and paper; the Type and Stage chips print (pressed ones ticked; founder 2026-11-02 reversed a national-7 change that hid them), the on-screen instructions do not, the "Showing ..." line does |

## Unresolved, and upstream dependencies

1. **Empty report outcome.** If every nearby record is excluded, the engine's outcome is still "No data ingested" (founder
   ruling R5 decides that wording and whether a free report is used). The report now adds "Records left out of this report",
   which says records were read and left out as routine or undescribed, ending "This is not a finding that there is no
   development nearby." The outcome word itself still needs a founder ruling.
2. **Coverage loss where sources publish no description** (above). Fix is upstream: ingest a work-class or description column
   per family, or the SEPA register's `proposaldescription`. Until then those records stay out.
3. **Descriptions are cut at 120 characters by every connector** (`SOURCE_TITLE_CAP`); `scope_text` is null for these sources.
   The report now cuts at a word and points to the official record, but the fuller text needs an ingest change.
4. **Grouping records into projects.** Records are cross-referenced by identical address only, and the report says they may or
   may not be one development. No linkage evidence (shared case ids) is available in the stored rows; Seattle's 400 4th Ave W
   shoring permit, phased building permit and MUP are shown as three records.
5. **Bumbershoot 2026 (Seattle Center installation).** The official record (Accela, fetched through `pg_net`) states: "open to
   the public from 9/5-9/6, load in will start 9/1 and all structures will be removed by 9/8". It is ENDED (window 2026-09-01 to
   09-08). The ingested title is cut at 120 characters before those dates and `scope_text` is empty, so the shared rule leaves it
   out as `temporary_timing_not_captured`, not as "no dates". With the full text the same rule reads it as ended (test T5).
   Reusable fix (not done here): connectors emit the full source description as `scope_text`, which `app_refresh_zip` already
   stores; it is shown in Map 1 popups, so it needs its own change, a connector deploy and a ZIP refresh. No dates are hard-coded.
6. **Browser print headers.** The supplied PDF was made with headers and footers off. A customer printing from Chrome still
   controls that setting; the hint on the PDF button says so.
7. **Residential "alterations"/"repairs".** For Residential records the canonical Map 1 rule calls a bare "alterations" or
   "repairs" routine; the report consumes that answer rather than restating it, so such a record is excluded as routine (not
   flagged for review). Building-wide, addition, change-of-use and the other significance rules run first, so they still win.
8. **Lifecycle engine untouched.** `presentationStage`/lifecycle keys are unchanged; only presentation and the unpublished-stage
   and temporary-event handling in the report changed.
9. **Not deployed.** The engine (`get-development-activity-report`) deploys only by manual dispatch. The view goes live with
   Pages on merge and re-renders saved reports (their routine work is hidden and the new labels apply).


## Follow-up, 2026-11-02 evening (founder "agree do all")

1. **Empty-report outcome: decided.** A fourth outcome, "No significant nearby changes found" (`NO_SIGNIFICANT_CHANGES`,
   `activity-outcome-2`), replaces "No data ingested" when the relevance rule read and left out every nearby record. It says how
   many records Jody checked and why each kind was left out. It does not use a free report (`credit-rule-2`), so charging is
   unchanged.
2. **Sources that publish a description column we never read: wired.** A shared connector helper
   (`get-address-report/sources/scope-text.ts`) carries a source's own work description as `scope_text`, which the relevance rule
   already reads and the change ledger ignores. Fields checked on each publisher's own layer through `pg_net` the same day:

   | Source family | description column | sample |
   |---|---|---|
   | brunswick-county-permits | `Description` | "New Home Stories: 1 … Sq. Ft. Under Roof: 3854" |
   | durham-building-permits | `DESCRIPTION` (not `COMMENTS`, which carries emails and owner names) | "SMPR: Kitchen remodel" |
   | cleveland-issued-building-permits | `WORK_DESCRIPTION` | "861 sq ft - Buildout of existing building." |
   | sioux-falls-building-permits | `WORKCLASS` | "Change in Use", "Reshingle" |

   | seattle-building-permits, seattle-land-use-permits | `description` (the full text; the label stays cut at 120) | Bumbershoot: "…removed by 9/8" |
   | wa-ecology-sepa-register | `proposaldescription` | "Divide 14.12 acres into 34 lots …" |

   Descriptions are cut at a word at 300 characters (Cleveland's cached rows were already ~6 MB), and emails and "User: …" account

3. **Where it takes effect:** a ZIP's stored records gain their descriptions when the rolling refresh next rewrites that ZIP

4. **The reader is already told** when nearby records do not describe their work ("Records left out of this report", and the
   new empty outcome's counts), so no further wording was added.
