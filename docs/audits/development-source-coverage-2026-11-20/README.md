## Why `data.json` is not committed
It is the Q12 export of production rows for the four test subjects (permit records with street addresses and free-text scope fields, plus ledger and event rows). It holds no subscriber data, but permit free text can contain names, so it is not committed. Regenerate it: run Q12 in `queries.sql`, save the result, then `node scripts/extract.mjs <saved-result.txt>`.

## Reproducing
1. Run Q12; save the result; `node scripts/extract.mjs <saved result>` writes `data.json`.
2. `node scripts/run.mjs` runs the real `get-development-activity-report` handler offline over S1-S4 at 0.5 mi and prints the handler's report object (counts, coverage warnings, included projects, relevance exclusions). `node scripts/cf.mjs` runs the 48854 counterfactual. Both scripts hard-code `/home/user/homesignal-site` and need Node 22 with type stripping.
   **The committed harness no longer reproduces the rendered headline text.** It does not load the report-view library under `lib/`. The rendered headline and "what the report would display" lines quoted in `REPORT-round2.md` came from the earlier local run, which also rendered the report HTML; they are not regenerated by these scripts.
3. For the inventory: run Q2, then `node scripts/build_inventory.mjs <saved result> <out dir> <registry ids json>`. The one committed inventory was produced by an equivalent inline script; `build_inventory.mjs` is the same transformation.
