# Batch 23 — prefixes 761 and 890 cut over (2026-09-04)

The two prefixes left behind when the batch-22 marker build stopped at the disk floor
mid-run. They held 20,017 authoritative memberships and **zero** markers, so they were
deliberately kept measured-not-cut-over: serving a ZIP whose markers are absent is the one
way to make Map 1 materially wrong, and the markerless-membership gate is what stops that
happening quietly.

WAL drained to 1,040 MB and free disk came back to 2,159 MB — 111 MB above the 2,048 floor
— so the marker build was re-run rather than cleanup being done first.

⚠️ **The CTE has to be `as materialized`, and this is not a style preference.** Without it
PostgreSQL inlines the CTE and calls the producer once per reference — three times per ZIP
in the verification query — so a group of five dense Fort Worth ZIPs exceeded the statement
timeout while the identical work with one call per ZIP finished in seconds. The first
reading of that was "the producer is too slow for this population", which was wrong: it was
being run three times. Anything that calls this producer more than once per row must
materialize.
