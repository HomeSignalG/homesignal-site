## Read this first

- **Unit: ZIP-page placements**, one per ZIP page a record is shown on (`public.app_projects` rows,
  `record_kind = development`). A record shown on four ZIP pages counts four times. This is what residents see,
  not the number of distinct government records.
- **"After" is the audit's PROPOSAL.** Every value marked `receipt`, `review` or `per_record` is still undecided
  and needs the founder's or an agency's answer before it is used. Until then those values show here as
  they would land with no receipt: Lifecycle unknown / undetermined, or "per record".
- **"per_record"** after-column = the column depends on the individual record (D1 pre-application, D3 completed
  work type) or on JODY's own observation history for an inactive record (§4.4). Not yet counted into a column.
- **"unmatched"** = a stored status that the audit has no row for (see the last section).
